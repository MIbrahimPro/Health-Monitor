# Phase 5 — Experimental Ambient Sensing: Sonar · Wi-Fi CSI · Ultrasonic Pairing

**Prerequisite:** Phases 1–4. These are experimental modules: each must be cleanly isolated, default OFF, and degrade to an explicit "Unavailable — reason" status rather than half-working. Audio modules must duck politely: never emit ultrasound while the music engine is playing through the same device unless mixing is verified.

## Step 1 — Audio I/O foundation `[x]`

**Goal:** Reliable full-duplex audio: emit a tone while capturing the mic, with sample-clock bookkeeping.

**Files:** new `aegis-core/src/sonar/audio.rs`

**Instructions:**
1. Enumerate devices; open default output at 48 kHz f32 and default input at 48 kHz (mono ok). If 48 kHz unsupported, take the nearest ≥44.1 kHz and store actual rates.
2. Output callback: phase-continuous sine generator `sin(2π f t)`, f settable atomically, amplitude 0.10 (LOW — 19 kHz at high volume can be unpleasant to pets/children; note this in code and UI).
3. Input callback: push samples into a lock-free ring (e.g. `crossbeam` bounded channel or a `Mutex<VecDeque>` drained fast — measure no overruns).
4. `bin/test_audio.rs`: emit 19 kHz for 5 s while recording; FFT the recording (rustfft, 8192 window); print the peak bin.

**Verify:** run `test_audio` — peak within ±30 Hz of 19 kHz and ≥20 dB above the noise floor (speaker+mic loopback through the air). If the mic can't hear 19 kHz (many laptop mics roll off), try 18.0/18.5/19.5 kHz and record the best frequency in STATE.md; if none rises ≥10 dB above floor, mark the whole phase's acoustic parts **hardware-blocked** in STATE.md and skip to Step 4.
**If it fails:** PipeWire device busy → `pw-top` to check; use `cpal` default host only, no ALSA direct.
**Commit:** `Full-duplex ultrasonic audio foundation with loopback self-test`

## Step 2 — Doppler motion sonar `[x]`

**Goal:** Detect room motion via Doppler sidebands around the carrier.

**Files:** `aegis-core/src/sonar/doppler.rs`

**Instructions:**
1. Continuous carrier at the calibrated frequency f0. On the input stream: sliding FFT (8192 @48 kHz → 5.86 Hz/bin, hop 2048).
2. Motion metric: `E_side / E_carrier` where `E_side` = sum of magnitude in bins f0±(15…120 Hz) (exclude ±2 bins around carrier), `E_carrier` = carrier bin magnitude. Calibrate 10 s of stillness at module start → baseline mean+σ; motion = metric > baseline + 4σ sustained ≥2 hops.
3. Output `motion_level: f32` (0–1 scaled by calibration) + `motion: bool` into a new `AmbientStats` event (don't overload VitalStats; separate Tauri event `ambient-update` at 4 Hz).
4. UI: minimal radar-style indicator card (pulse ring on motion) per design tokens.

**Verify:** sit still 15 s (no motion flag), wave an arm at 1 m → flag within 1 s; walk behind the chair → flag. Log SNR numbers into STATE.md.
**Commit:** `Doppler sonar motion detection with self-calibration and ambient event stream`

## Step 3 — Respiration-by-sonar (stretch, optional) `[x]`

**Goal:** Micro-Doppler chest movement → breaths/min; cross-check with the camera respiration.
**Instructions:** narrow analysis to f0±(0.2…2 Hz) using a 2^17 FFT (2.7 s) on the complex demodulated carrier (multiply input by e^{-i2πf0t}, low-pass 5 Hz, then Welch in 0.13–0.55 Hz). If the camera resp and sonar resp agree within ±3/min over 2 min → mark validated.
**Verify:** side-by-side log 3 min. If it never converges, mark optional-abandoned (fine) — remove nothing.
**Commit:** `Sonar micro-Doppler respiration estimate cross-checked with camera`

## Step 4 — Wi-Fi CSI interface (documentation-first) `[x]`

**Goal:** Honest CSI support: a clean trait + status reporting; real capture only if supported hardware/drivers exist (rare: Intel 5300 with CSI Tool, or nexmon-patched broadcom).

**Files:** new `aegis-core/src/csi.rs`, `docs/csi-setup.md`

**Instructions:**
1. `trait CsiSource { fn probe() -> Availability; fn start(...) }` with `Availability::{Available, MissingDriver(String), UnsupportedHardware(String)}`.
2. `probe()`: check `lspci`/`lsusb` output for known CSI-capable NICs, check for nexmon interfaces (`/sys/class/net/*/device` + `iw list` monitor support). On this machine it will almost certainly return Unsupported — that's success, reported truthfully in the UI ("CSI: unsupported NIC (…)").
3. `docs/csi-setup.md`: exact nexmon/Intel-CSI setup instructions for supported hardware, and the parser format the module expects (nexmon UDP frames) so a future contributor can finish `NexmonSource`.
4. Implement `NexmonSource::start` reading the documented UDP format into amplitude vectors + a motion metric (variance over subcarriers) — code-complete but only runnable on real hardware.

**Verify:** `probe()` unit test with mocked sysfs strings; UI shows the truthful unavailable status; build clean.
**Commit:** `Wi-Fi CSI module: capability probe, nexmon source, honest unavailable states`

## Step 5 — Ultrasonic air-gapped pairing (FSK) `[x]`

**Goal:** Desktop broadcasts an ultrasonic challenge; a trusted device answers with an HMAC — proximity token. (Phone side arrives in P6; this step ships the protocol + a desktop↔desktop/loopback test.)

**Files:** new `aegis-core/src/sonar/pairing.rs`

**Instructions:**
1. Modulation: binary FSK, bit0=18.2 kHz, bit1=19.4 kHz (use Step 1's calibrated usable band; keep ≥800 Hz separation), 50 ms/bit (20 bps — slow but robust), 100 ms guard silence between frames.
2. Frame: preamble 10101011 ×2 → length byte → payload → CRC16. Demod: Goertzel at both frequencies per 25 ms half-bit, majority vote per bit, sync on preamble correlation.
3. Protocol: `challenge = 8 random bytes`; response = `HMAC-SHA256(shared_secret, challenge)[..8]`. Shared secret: 32 bytes generated at first run, shown as QR in UI settings (QR lib: `qrcode` crate rendering to SVG string — display in dashboard). Dep: `hmac`, `sha2`, `rand`, `qrcode`.
4. `bin/test_pairing.rs --loopback`: encode a challenge to a WAV, decode it back (pure DSP loopback, no audio), assert round-trip; `--air` mode: play + listen on the same machine (speaker→mic) and decode own transmission.
**Verify:** loopback test in CI (`cargo test`); air test decodes ≥9/10 frames at 50 cm. If air fails but loopback passes → lower to 25 ms Goertzel windows or increase bit time to 80 ms; if the hardware band is dead (Step 1), keep loopback-verified protocol and mark air-blocked.
**Commit:** `Ultrasonic FSK pairing protocol with HMAC challenge-response and loopback tests`
