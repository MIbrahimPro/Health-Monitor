# Phase 4 — Security: Face Recognition · Shoulder-Surfing · Input Biometrics

**Prerequisite:** Phases 1–3. **Privacy is law in this phase**: never store raw keystrokes (timings only), never store face images (embeddings only), everything local, all modules default OFF with explicit UI enrollment flows.

---

## Step 1 — Owner face enrollment + verification `[x]`

**Goal:** Recognize whether the person at the camera is the enrolled owner via face embeddings + cosine similarity.

**Files:** new `aegis-core/src/facerec.rs`, model `models/mobilefacenet.onnx` (or `arcfaceresnet100-8.onnx` if size acceptable; prefer MobileFaceNet ~4 MB, input `1x3x112x112`, output 128/512-d embedding)

**Instructions:**
1. Preprocess: crop the detected face box + 15 % margin, bilinear-resize 112×112, RGB, normalize `(x-127.5)/128`. (No landmark alignment v1 — rustface gives no landmarks; frontal desk use tolerates it. Note the accuracy tradeoff in code comments.)
2. `embed(frame, facebox) -> Vec<f32>` (L2-normalized). `cosine(a,b)`.
3. Enrollment command `enroll_owner`: capture 15 embeddings over 10 s (varied micro-poses), store the MEAN embedding (re-normalized) in the config dir as `owner.embed` (raw f32 bytes + version header). Command `clear_owner`.
4. Verification loop (1 Hz on detection thread): `is_owner = cosine(current, owner) > 0.55` smoothed over 5 samples (≥3 of 5). Threshold 0.55 is a starting point — see Verify for tuning.
5. `owner_present: Option<bool>` into VitalStats/payload; config `facerec_module` default off.

**Verify:** enroll yourself; check similarity logs: self ≥0.7 typical, and test with a photo of a different face (phone screen held up) < 0.4. If your self-similarity dips below the threshold on head turns, lower to 0.50 and re-test both directions. Record chosen threshold in STATE.md.
**If it fails:** tract can't run the model → try the ONNX zoo `arcfaceresnet100-8` (larger but well-supported); still failing → blocked note.
**Commit:** `Owner face enrollment and verification via MobileFaceNet embeddings`

## Step 2 — Shoulder-surfing detection `[x]`

**Goal:** If >1 face is present for >2 s, trigger privacy response (frost overlay + event).

**Files:** `camera.rs` (detection thread already gets all faces), `facerec.rs`, overlay wiring

**Instructions:**
1. Detection thread: count faces above min size (≥40 px at detect scale — tune so background posters don't count); pass `face_count` through the shared state alongside the primary box.
2. `face_count ≥ 2` sustained 2 s (flicker-tolerant: ≥4 of last 6 half-second samples) → `shoulder_surfing: true` in stats; if config `privacy_auto_frost` on → overlay frost 0.9 fast (300 ms) + danger toast in UI. Clears when count <2 for 3 s.
3. Snooze command (`privacy_snooze(mins)`) for pair-programming sessions.

**Verify:** manual with a second person or a printed face photo held next to you → frost within ~2.5 s, clears on removal; snooze works.
**Commit:** `Shoulder-surfing detection with auto-frost privacy response and snooze`

## Step 3 — Keystroke & mouse dynamics capture `[x]`

**Goal:** Global input timing capture (dwell/flight, mouse velocity) — timings ONLY.

**Files:** new `aegis-core/src/biometrics.rs`, dep `rdev = "0.5"`

**Instructions:**
1. **Linux reality check first**: `rdev` listen on Wayland generally fails (needs X11 or root evdev). Try `rdev::listen` in a `bin/test_input.rs`; if it errors on this session type, implement the evdev path: dep `evdev = "0.12"`, read `/dev/input/event*` — requires the user to be in the `input` group. If neither works without sudo, ASK THE USER: `sudo usermod -aG input $USER` + relogin, and gate the module as unavailable until then.
2. Capture thread → ring buffers:
   - Keyboard: per key-code (NOT mapped to characters — store scancode only) `press_t`, compute dwell (press→release) and flight (release→next press). Bucket into a 16-bucket histogram each (5 ms bins, 0–80+ ms overflow bucket) per rolling 60 s.
   - Mouse: sample velocity (px/100 ms), acceleration; 16-bucket histograms.
3. NO raw sequences persisted. Only histograms + summary stats (mean/std) in memory; profile persisted only via Step 4 enrollment.

**Verify:** `bin/test_input.rs` prints live dwell/flight stats while you type; confirm no keycode→char mapping anywhere (`grep -i "char\|keysym" src/biometrics.rs` returns nothing suspicious).
**Commit:** `Input biometrics capture: dwell/flight and mouse dynamics histograms (timings only)`

## Step 4 — Typing-rhythm anomaly detection `[x]`

**Goal:** Enroll the owner's rhythm; score live rhythm; sustained anomaly → configurable action.

**Files:** `biometrics.rs`

**Instructions:**
1. Enrollment: `enroll_typing` accumulates 5+ minutes of active typing histograms → store normalized reference histograms in config dir (`typing.profile`).
2. Live score at 30 s cadence over the last 60 s (only if ≥40 keystrokes in window): distance = Jensen-Shannon divergence between live and reference (dwell + flight averaged). Calibrate: during the 2nd enrollment session, record the owner's own JSD distribution; threshold = mean + 3σ (auto-computed, stored).
3. Anomaly sustained 2 consecutive windows → event `intruder_suspected` → actions per config: `notify` (default) / `frost` / `lock` (lock = `loginctl lock-session`, command exists on systemd).
4. False-positive guard: owner face verified (Step 1) within last 30 s → suppress.

**Verify:** unit test JSD math vs known distributions; live: type normally 2 min (no alarms), then ask someone else (or type one-handed deliberately) 2 min → alarm fires; with face verified, suppressed.
**Commit:** `Typing-rhythm anomaly detection with JSD scoring, auto-threshold, and safe actions`
