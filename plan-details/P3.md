# Phase 3 — Posture · Emotion · Smart Music

**Prerequisite:** Phases 1–2 done. Posture reuses the face box from the camera loop; emotion adds one small ONNX model; the music engine is standalone (rodio) and connects to emotion.

---

## Step 1 — Posture estimation from the face box `[ ]`

**Goal:** Detect slouching/leaning-in using the tracked face box (no landmarks needed): face size ratio ≈ distance to screen; vertical center drop ≈ slouch.

**Files:** new `aegis-core/src/posture.rs`, wire in `camera.rs`

**Instructions:**
1. `PostureMonitor` with:
   - Calibration: first 30 s with a face → store median box height `h0` and median center-y `cy0` (median over samples, robust to outliers). Expose `recalibrate()`.
   - Per frame: `dist_ratio = h / h0` (>1 = closer), `drop_ratio = (cy - cy0) / frame_h`.
   - State machine: `Good`, `TooClose` (dist_ratio > 1.28 sustained 20 s), `Slouching` (drop_ratio > 0.06 AND dist_ratio > 1.10 sustained 30 s). Sustained = condition true ≥ X of the last X+5 seconds (ring buffer of per-second booleans — tolerate flicker).
2. Add `posture: String` (or enum serialized) to `VitalStats` → payload.
3. Config toggle `posture_module`, default on (it's free — no extra compute).

**Verify:** unit test the state machine with synthetic sequences (good→lean-in→good; flickering condition must NOT trigger). Live: lean toward the camera 25 s → UI state changes.
**Commit:** `Posture monitor: calibrated face-box distance/slouch state machine`

## Step 2 — Posture → overlay correction loop `[ ]`

**Goal:** Per plan.md 3.1: sustained bad posture progressively frosts the screen via the P2 overlay; correcting posture clears it instantly.

**Files:** `aegis-ui/src-tauri/src/lib.rs`, `aegis-ui/public/overlay.html`

**Instructions:**
1. overlay.html: add `setFrost(level)` (0–1): a translucent desaturating layer — white at `opacity level*0.28` + the grain at `opacity level*0.15` + an inset vignette. (True gaussian blur of the desktop is NOT possible from a transparent overlay window — do not attempt; frost+dim is the honest effect.)
2. Backend: when posture state != Good for its sustained window, ramp frost 0→0.8 over 20 s (tokio task, 500 ms ticks, only while overlay window exists — create it on demand even if warmth is 0). When posture returns Good: animate frost→0 over 600 ms then close overlay if warmth==0.
3. Never frost while `phone_detected` handling or a fullscreen app... keep it simple: config `posture_enforce` default **off**; when off, posture only shows in UI (nagging visuals are opt-in).

**Verify:** manual: enable enforce, slouch 30 s+ → screen frosts gradually; sit up → clears <1 s.
**Commit:** `Posture-linked screen frosting via overlay with instant recovery`

## Step 3 — Facial emotion recognition `[ ]`

**Goal:** Classify Neutral/Happy/Sad/Angry/Surprised etc. → map to {Neutral, Happy, Stressed, Fatigued, Sad}; smooth over 10 s.

**Files:** new `aegis-core/src/emotion.rs`, model `models/emotion-ferplus-8.onnx`

**Instructions:**
1. Model: **emotion-ferplus-8** from the ONNX model zoo (~34 MB... actually ~1.6 MB, input `1x1x64x64` grayscale, output 8 logits: neutral, happiness, surprise, sadness, anger, disgust, fear, contempt). Ask the user to download if no network; place in `models/`.
2. `emotion.rs`: crop the face box (full box, not ROI) from the gray frame, resize to 64×64 (nearest is fine; write a small bilinear helper for quality), normalize per model card (raw 0-255 float works for ferplus), tract session, softmax, EMA the probability vector over 10 s (α=0.1 at 1 Hz — run at 1 fps on the detection thread cadence).
3. Mapping: happiness→Happy; sadness→Sad; anger|disgust|contempt→Stressed; fear|surprise→Stressed; neutral→Neutral; add Fatigued = (neutral prob >0.6 AND eye-region variance low)… skip Fatigued if unreliable — better honest 4 states than fake 5. Document the choice.
4. `emotion: Option<String>` into VitalStats/payload; config toggle `emotion_module` default off.

**Verify:** `bin/test_emotion.rs <image>` prints class probabilities; smile at the camera → Happy within ~10 s in UI logs.
**If it fails:** tract op unsupported → try `emotion-ferplus-2` (older opset). Still failing → mark blocked, continue.
**Commit:** `Facial emotion recognition (FER+ ONNX) with 10s smoothing and state mapping`

## Step 4 — Local music engine: scan + tag `[ ]`

**Goal:** Scan `~/Music`, decode, extract features (tempo, energy, brightness), auto-tag {Calm, Focus, Energetic, Sad, Motivational}, store in SQLite.

**Files:** new `aegis-core/src/music/{mod.rs,analyze.rs,library.rs}`, deps: `rodio = "0.17"` (playback, next step), `symphonia = { version="0.5", features=["mp3","flac","isomp4","aac"] }` (decode), reuse `rusqlite`

**Instructions:**
1. `library.rs`: walk `~/Music` (config key `music_dir`) for mp3/flac/m4a; store `tracks(path PRIMARY KEY, title, artist, duration, bpm REAL, energy REAL, brightness REAL, tag TEXT, analyzed_at)`; skip already-analyzed (mtime check).
2. `analyze.rs` per track (decode middle 60 s to mono f32 44.1k via symphonia):
   - **Tempo**: onset strength = positive spectral-flux of 2048-pt STFT hop 512; autocorrelate the onset envelope over 60–180 BPM lags; pick max → `bpm`.
   - **Energy**: RMS of the waveform (normalized 0–1 by full-scale).
   - **Brightness**: spectral centroid mean (Hz, normalize /8000 clamp 0–1).
3. Tagging rules: bpm<90 & energy<0.3 → Calm; 90–120 & brightness<0.5 → Focus; >120 & energy>0.5 → Energetic; bpm<100 & brightness<0.35 & minor-ish (skip key detection — use brightness<0.3) → Sad; >115 & brightness>0.55 → Motivational; else Focus.
4. Analysis runs on a background thread with progress events (`music-scan-progress`).

**Verify:** unit test tempo estimation on a generated click track (synth 120 BPM clicks → 120±3). Run scan on the user's `~/Music` (ask them if it's ok / exists; else create 2 test tones): `select tag, count(*) from tracks group by tag;` shows a sane spread.
**Commit:** `Music library: symphonia analysis (tempo/energy/brightness) with auto-tagging`

## Step 5 — Smart player + emotion linkage `[ ]`

**Goal:** rodio playback with queue by tag, crossfade, and auto-selection from emotion.

**Files:** `aegis-core/src/music/player.rs`, Tauri commands, UI panel

**Instructions:**
1. `Player`: rodio `OutputStream` + two `Sink`s for crossfade (fade out old over 3 s while new fades in — volume ramp on a 50 ms tick thread). Commands: play_tag(tag), pause, resume, skip, now_playing, set_volume.
2. Auto-selector (config `music_auto` default off): on smoothed emotion Stressed ≥60 s → crossfade to Calm; Sad → Motivational... follow plan.md: Stressed→Calm/Focus. Only switch if current tag differs and ≥90 s since last auto-switch (no thrash).
3. UI: mini-player card (track, tag chip, play/pause/skip, volume) in design tokens.

**Verify:** manual: play a tag, hear crossfade on skip; force emotion state via a dev command → auto-switch fires once.
**Commit:** `Smart music player: crossfading rodio sinks with emotion-driven auto-selection`
