# Phase 6 — Mobile Companion & Release Polish

**Prerequisite:** Phases 1–5.

## Step 0 — DECISION NEEDED FROM THE USER `[ ]`

Two viable companion architectures — **ask the user which one before writing any code**:

- **Option A — LAN PWA (recommended):** the daemon serves a mobile-optimized web dashboard over the local network (axum HTTP+WebSocket in Rust). Zero app-store friction, works on any phone browser, one codebase, ships in days. Limitation: browser mic access for the sonar-node role requires HTTPS (self-signed cert dance) and background operation is limited.
- **Option B — Flutter app:** native app as `plan.md` envisioned (RN/Flutter). Full mic/background capabilities for pairing + sonar node, but a whole second project (SDKs, signing, device testing).

Present exactly this tradeoff. If the user is unavailable after asking, implement Option A (it satisfies "view stats + remote control" fully) and leave Option B as a documented follow-up. Record the decision in STATE.md.

## Step 1 — LAN API server in the daemon `[ ]` (both options need it)

**Files:** `aegis-daemon/src/main.rs` → real daemon; new `aegis-core/src/server.rs`; deps `axum = "0.7"`, `tokio-tungstenite` via axum ws, `tower-http = { features=["fs","cors"] }`

**Instructions:**
1. Endpoints: `GET /api/status` (modules, uptime), `GET /api/vitals` (latest VitalStats JSON), `WS /api/stream` (push VitalStats+AmbientStats at 2 Hz), `POST /api/toggle {module, on}` (auth required), `GET /` (serves the mobile web app of Step 2).
2. Auth: bearer token = the Phase-5 shared secret (hex). Reject without it (except `/`). Bind `0.0.0.0:8817`; print + show in UI a connect QR: `http://<lan-ip>:8817/#<token>`.
3. The daemon becomes the real headless host: camera loop + modules per config + server. Tauri app keeps its embedded loop (unchanged) — do NOT run both against one camera; daemon refuses if `/dev/video0` busy with a clear message.

**Verify:** `curl -H "Authorization: Bearer <token>" localhost:8817/api/vitals` returns JSON; wrong token → 401; `websocat` streams frames. Phone on same Wi-Fi loads the page.
**Commit:** `LAN API: axum server with token auth, vitals stream, and module control`

## Step 2 — Mobile web dashboard `[ ]` (Option A)

**Files:** new `aegis-mobile/` (vite + react, reuse the design system CSS tokens — copy, don't link), built output served by Step 1.

**Instructions:** one screen, mobile-first: connect via `#token` from QR → live HR hero, respiration, quality ring, intent chip, motion indicator, module toggles (POST /api/toggle). Reconnect logic with backoff. Add PWA manifest + service worker for home-screen install. Build integrated into `scripts/build_mobile.sh` copying `dist/` into the daemon's static dir.
**Verify:** phone: install to home screen, kill/reopen → reconnects; toggles work end-to-end; UI matches the Aegis design language.
**Commit:** `Mobile PWA companion: live vitals dashboard with remote module control`

## Step 3 — Pairing token role `[ ]` (Option A partial / Option B full)

**Instructions:** PWA "Presence" tab: getUserMedia mic capture → Goertzel at the two FSK freqs in a WorkletNode, decode the desktop's ultrasonic challenge, answer via WebSocket (`POST /api/pairing/answer` with HMAC using the shared token). Desktop treats a correct answer within 3 s of broadcast as proximity-verified (it heard the room's audio). Note honestly: WS answer proves shared-key + LAN, ultrasound hearing proves physical presence.
**Verify:** phone in the room → presence verified events; phone in another room (door closed) → fails.
**Commit:** `Companion presence: ultrasonic challenge heard by phone, HMAC answer over LAN`
